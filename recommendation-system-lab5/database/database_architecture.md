# Архитектура базы данных рекомендательной системы

## 1. Выбранный датасет

В качестве основы используется датасет **The Movies Dataset**. Он содержит информацию о фильмах, жанрах, ключевых словах, рейтингах пользователей и дополнительных метаданных.

Датасет подходит для разработки рекомендательной системы, потому что содержит два основных типа данных:

1. **Контентные признаки фильмов**: название, описание, жанры, ключевые слова, год выпуска, популярность.
2. **Пользовательские взаимодействия**: оценки пользователей фильмам.

Это позволяет реализовать три подхода:

- фильтрацию по содержимому;
- коллаборативную фильтрацию;
- гибридную рекомендательную систему.

---

## 2. Основные таблицы базы данных

### Таблица `users`

Хранит информацию о пользователях.

| Атрибут | Тип | Описание |
|---|---|---|
| `user_id` | INTEGER, PK | Уникальный идентификатор пользователя |
| `created_at` | TEXT | Дата добавления пользователя в систему |

В исходном датасете нет демографических данных пользователей, поэтому таблица содержит минимальную информацию. При необходимости её можно расширить полями `age`, `gender`, `country`, `favorite_genre`.

---

### Таблица `movies`

Хранит информацию о фильмах.

| Атрибут | Тип | Описание |
|---|---|---|
| `movie_id` | INTEGER, PK | Уникальный идентификатор фильма |
| `title` | TEXT | Название фильма |
| `original_title` | TEXT | Оригинальное название |
| `overview` | TEXT | Описание фильма |
| `release_date` | TEXT | Дата выхода |
| `release_year` | INTEGER | Год выхода |
| `runtime` | REAL | Длительность фильма |
| `adult` | INTEGER | Признак фильма для взрослых |
| `budget` | REAL | Бюджет |
| `revenue` | REAL | Сборы |
| `popularity` | REAL | Популярность |
| `vote_average` | REAL | Средняя оценка |
| `vote_count` | INTEGER | Количество оценок |
| `original_language` | TEXT | Язык оригинала |

Эта таблица используется для фильтрации по содержимому, так как содержит признаки фильмов.

---

### Таблица `ratings`

Хранит оценки пользователей.

| Атрибут | Тип | Описание |
|---|---|---|
| `rating_id` | INTEGER, PK | Уникальный идентификатор оценки |
| `user_id` | INTEGER, FK | Пользователь, который поставил оценку |
| `movie_id` | INTEGER, FK | Фильм, которому поставлена оценка |
| `rating` | REAL | Значение оценки |
| `timestamp` | TEXT | Время выставления оценки |

Эта таблица является основной для коллаборативной фильтрации. На её основе строится матрица пользователь–фильм.

---

### Таблица `genres`

Хранит список жанров.

| Атрибут | Тип | Описание |
|---|---|---|
| `genre_id` | INTEGER, PK | Уникальный идентификатор жанра |
| `name` | TEXT | Название жанра |

---

### Таблица `movie_genres`

Связующая таблица между фильмами и жанрами.

| Атрибут | Тип | Описание |
|---|---|---|
| `movie_id` | INTEGER, FK | Идентификатор фильма |
| `genre_id` | INTEGER, FK | Идентификатор жанра |

Связь между фильмами и жанрами имеет тип многие-ко-многим: один фильм может иметь несколько жанров, и один жанр может относиться ко многим фильмам.

---

### Таблица `keywords`

Хранит ключевые слова фильмов.

| Атрибут | Тип | Описание |
|---|---|---|
| `keyword_id` | INTEGER, PK | Уникальный идентификатор ключевого слова |
| `name` | TEXT | Название ключевого слова |

---

### Таблица `movie_keywords`

Связующая таблица между фильмами и ключевыми словами.

| Атрибут | Тип | Описание |
|---|---|---|
| `movie_id` | INTEGER, FK | Идентификатор фильма |
| `keyword_id` | INTEGER, FK | Идентификатор ключевого слова |

Ключевые слова используются для построения контентного профиля фильма.

---

## 3. Обоснование структуры базы данных

Выбранная структура базы данных соответствует задачам рекомендательной системы.

### Для Content-Based Filtering

Используются таблицы:

- `movies`;
- `genres`;
- `movie_genres`;
- `keywords`;
- `movie_keywords`.

Они позволяют сравнивать фильмы по жанрам, описанию, ключевым словам, году выпуска и другим признакам.

### Для Collaborative Filtering

Используются таблицы:

- `users`;
- `movies`;
- `ratings`.

На основе таблицы `ratings` можно построить матрицу пользователь–фильм и находить похожих пользователей или похожие фильмы.

### Для Hybrid Methods

Гибридная система может объединять:

- похожесть фильмов по содержимому;
- оценки пользователей;
- популярность фильмов;
- жанровые предпочтения.

Таким образом, структура БД поддерживает все основные методы рекомендательных систем.

---

## 4. Связи между таблицами

Основные связи:

1. `users` → `ratings`: один пользователь может поставить много оценок.
2. `movies` → `ratings`: один фильм может получить много оценок.
3. `movies` → `movie_genres` → `genres`: фильм может иметь несколько жанров.
4. `movies` → `movie_keywords` → `keywords`: фильм может иметь несколько ключевых слов.

Такая структура нормализована и уменьшает дублирование данных.

---

## 5. Вывод

Разработанная база данных подходит для построения функциональной рекомендательной системы. Она хранит как информацию о фильмах, так и данные о пользовательских оценках, что позволяет реализовать фильтрацию по содержимому, коллаборативную фильтрацию и гибридные методы.
